ATTACK 1 [MAJOR] HERMÈS's headline scenario needs unpaid client invoices that no agent can produce
Where: HERMÈS scenario, line 206: "demande à CRÉSUS les factures impayées de ce client (2 factures, 3 400 €)"; asserted again in Synergie line 313 ("HERMÈS ↔ CRÉSUS | factures d'un client, statut de paiement | dossier de créance, relances d'impayés") and in the "Santé clients" widget (line 217). CRÉSUS capabilities: lines 43, 45, 48.
Problem: CRÉSUS is defined only over invoices the user RECEIVES and PAYS — Factur-X "factures fournisseurs" (line 43), reconciliation "facture ↔ débit" that matches an invoice to an outgoing bank debit (line 45), and tables transactions/positions/exposures/invoices fed from the casiers banque+factures (line 48). It is never given any source for invoices the user ISSUES to B2B clients, and an unpaid receivable by definition has no matching bank debit, so CRÉSUS's debit-matching pipeline structurally cannot surface one. Even if an issued-invoice PDF reached the "factures" casier, CRÉSUS's only described invoice logic treats invoices as payables to reconcile against debits. The "2 factures, 3 400 € impayées," the déclaration-de-créance dossier, and the impayés relances therefore rest on data the system has no mechanism to hold. The second half of HERMÈS's single day-in-the-life ("une seule tâche, avec deux résultats", line 197) collapses.

ATTACK 2 [MAJOR] ARGOS's "no keywords" differentiator is refuted by its only worked example
Where: line 89 ("tu ne lui donnes pas de mots-clés ... il repère les sujets par anomalie de volume avant de dépenser le moindre appel LLM"); line 100 (the LLM is used "sur les pics seulement"); scenario line 110 (watchlist entity = country:TW, added by CRÉSUS; GDELT query = "Taiwan (blockade OR military OR sanctions)").
Problem: The only watchlist input CRÉSUS supplies is country:TW, and the text states the LLM is not called until after a spike is detected, so the GDELT query must be built pre-LLM from the bare entity. Yet the scenario's query carries three hand-picked risk terms — blockade, military, sanctions — with no stated origin: not the user (claim: no keywords), not CRÉSUS (supplies country:TW only), not the LLM (runs later). Either detection runs on bare "Taiwan" volume, in which case the scenario's query is wrong and unexplained, or risk terms are injected, in which case "sans mots-clés" is false. The step that turns an entity into a query is missing, and the single concrete demonstration of the keyword-free mechanism contradicts the mechanism it is meant to prove.

ATTACK 3 [MINOR] ARGOS cannot surface "news on your clients," so the HERMÈS→ARGOS synergy is dead for ordinary clients
Where: Synergie line 312: "HERMÈS → ARGOS | clients et prospects (siren:…) → watchlist | actualités dans la fiche CRM et avant un rendez-vous." ARGOS detection methods: GDELT volume anomaly (lines 95, 100), RSS feeds (line 96), watched pages (lines 98-99).
Problem: ARGOS's engine is volume-anomaly detection over GDELT plus a fixed set of press/think-tank/institution RSS feeds and manually-watched pages. A siren: entity is a French company, and the clients HERMÈS finds via BODACC are ordinary SMEs that generate essentially zero global-news coverage, so GDELT timelinevol stays near 0 and never spikes; there is no per-company RSS feed among ARGOS's sources; and nothing auto-adds each client's website as a watched page. Counterexample: any SME client written to the watchlist yields no ARGOS signal, so "actualités dans la fiche CRM et avant un rendez-vous" produces nothing for the typical client. A synergy link that directive 3 explicitly asks for is non-functional for its common input.
