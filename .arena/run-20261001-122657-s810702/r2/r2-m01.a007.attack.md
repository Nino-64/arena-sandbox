ATTACK 1 [MINOR] Concurrent-tab merge silently drops cumulative stats, contradicting its own guarantee
Where: `mergeInto` (solution lines 89-94) and its comment: "so two open tabs never erase each other's records"; narrative line 17 "records by max".
Problem: `games`, `orbs`, and `totalScore` are running TOTALS, but they are merged with `Math.max` just like the genuinely monotonic `best`/`bestCombo`. Counterexample: both tabs load disk `{games:10}`. Tab A finishes a run -> local games=11, persist writes 11. Tab B (also started at 10) finishes a run -> local games=11, persist reads disk(11), `max(11,11)=11`, writes 11. Two runs were played but the stored count is 11, not 12 — one run's increment is erased. Same loss applies to `orbs` and `totalScore` under simultaneous play. This directly falsifies the "never erase each other's records" claim for those three fields (best/bestCombo are fine). Narrow edge case (two concurrent tabs), hence MINOR.

ATTACK 2 [MINOR] False claim: "fixed 1/120 s sub-steps"
Where: write-up line 16 "The simulation runs in fixed 1/120 s sub-steps no matter the refresh rate." Code: `const n = Math.max(1, Math.ceil(dt / SIM_STEP)); for (...) step(dt / n);` (lines 568-569), `SIM_STEP = 1/120` (line 28).
Problem: the sub-step size is `dt/n`, not a fixed 1/120 s. Counterexample: at 90 fps full speed, `dt≈0.0111`, `n=ceil(1.33)=2`, sub-step `≈0.00555 s = 1/180 s`, not 1/120. The step is only *bounded* at `≤1/120 s`; it varies with refresh rate. The anti-tunneling property still holds, so this is a wrong statement in the documentation rather than a gameplay failure — MINOR.

ATTACK 3 [MINOR] Self-contradictory death-to-restart timing figures
Where: line 14 "the fastest way from dying to playing again is about 0.65 s" vs line 85 test log "about 0.75 s from death to a new run".
Problem: the same deliverable reports two different numbers for the same quantity. The constants give a floor of `DEATH_SKIP(0.35) + RESTART_GUARD(0.3) = 0.65 s` (line 14), but the recorded test (tap at 0.4 s + 0.32 s) is 0.72 s, rounded to 0.75 s. The user reading the doc gets inconsistent expectations. Purely a documentation inconsistency, no functional impact — MINOR.
