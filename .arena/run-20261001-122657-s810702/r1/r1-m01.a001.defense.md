ATTACK 1: CONCEDE. This is correct. In headless Chromium on the original, a mouse click on mute focused the button, and the next `Space` toggled the sound instead of launching, so the planet collapsed. Fix: HUD buttons now `preventDefault` on `mousedown` so a click never focuses them. During a run, `Space`/`Enter` also blur any focused HUD button and launch. Chromium now reports focus on BODY, the run continues and the sound setting does not change. Testing also showed that the menu screens (z-index 10) covered the HUD (z-index 5), so mute could not be clicked on the menu or results screens. The HUD is now at z-index 20.
ATTACK 2: CONCEDE. This is correct. In the original, `elementFromPoint` 100 ms after tap-to-retry returned the fading `#over` section. Fix: `.screen:not(.show){pointer-events:none}`, so the same check now returns the game canvas.
ATTACK 3: CONCEDE. Touch players now have a restart button in the HUD, shown only during a run. A tap, `Space` or `Enter` during the death animation restarts at once, starting 0.35 s after the death; that guard stops a launch tap from restarting by accident. `R` now also works while the death animation plays. The results screen appears at 0.7 s instead of 0.9 s, and its input guard is 0.15 s instead of 0.3 s. All of this was checked in Chromium.
ATTACK 4: CONCEDE. This is correct: the launch, trail and ring particles skipped the cap. All of them now go through one `addParticle()` function that enforces `MAX_PARTICLES = 700`, so `burst()` is the only other place that adds particles and it uses the same function.
ATTACK 5: CONCEDE. `user-scalable=no` is removed, so pinch-zoom works. `touch-action:manipulation` on the page and `touch-action:none` on the canvas still stop double-tap zoom and gestures from getting in the way of play.
