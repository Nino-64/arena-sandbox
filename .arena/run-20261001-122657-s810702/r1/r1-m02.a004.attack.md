ATTACK 1 [MAJOR] Hidden overlay screens keep catching taps for 280 ms, so the first taps after Resume (and after Play/Retry) are lost while hazards are live
Where: CSS `.screen{...opacity:0;visibility:hidden;transition:opacity .28s,visibility 0s linear .28s;...}` together with `resume()` → `showScreen(null)`, and the flip handler being bound only to the canvas: `cv.addEventListener('pointerdown', ... if (G.mode === 'play') flip())`.
Problem: When `.show` is removed, `visibility` changes only after a 0.28 s delay. Until then the full-screen `<section>` (`position:fixed;inset:0`, later in the DOM than the canvas, no `pointer-events:none`) still covers the canvas and receives every pointer event. Counterexample: you are on the inner orbit with an armed mine about 0.3 rad ahead. You pause, then tap Resume and tap again within 280 ms to switch orbit. `G.mode` is already `'play'`, so the simulation runs, but the second tap lands on `#pause`, which has no handler for it. No flip happens and you hit the mine. The same thing happens at the start of every run: after a tap on the summary, the next taps within 280 ms land on `#over`, whose handler calls `tryRestart()`, which returns because the mode is not `'over'`. Keyboard input is not affected, so only touch and mouse players lose inputs. This works against requirement 1 ("instant restart loops") and the "responsive" requirement.

ATTACK 2 [MAJOR] R mid-run and "Menu" from pause throw the run away: a new high score, the collected shards, XP and achievements are never saved
Where: `keydown` → `else if (k === 'KeyR') startRun();` while playing, and `$('quitBtn')` → `toMenu()`. Neither one calls `finishRun()`, which is the only code that writes `best`, `shards`, `xp`, `runs` and `ach` to the save.
Problem: Requirement 4 asks for "Save systems (high scores, progression, unlockables using LocalStorage)". Counterexample: the saved best is 1,200. During a run you reach 3,000 points and pick up 40 shards. You press R, which the doc advertises as "Instant restart … R (during a run…)", or you pause and press Menu. `save.best` stays 1,200 and the wallet doesn't get the 40 shards, so no XP, no level-up bonus and no "Warm Orbit"/"Event Horizon" achievement are awarded. The HUD showed "Best 3,000" during the run because of `Math.max(save.best, s)`, so the player believes the record was set. Nothing warns that the restart discards the run.

ATTACK 3 [MAJOR] On a landscape phone the summary screen overflows, and any attempt to scroll it restarts the run, so Skins and Menu cannot be reached
Where: `$('over').addEventListener('pointerdown', (e) => { if (!e.target.closest('button')) tryRestart(); });` with `.screen{...padding:24px 16px;overflow-y:auto}`.
Problem: The summary card stacks the eyebrow (~27 px), `.big` (104 px × 0.95), the badge, which takes up space even while `visibility:hidden` (~54 px), the meta tiles (~88 px), the XP block (~68 px), the goal line (~38 px), the button row (52 px) and the keys line (~41 px). That is about 470 px of content plus 48 px of padding, against a viewport height of about 390 px on an 844×390 landscape phone. To reach the Skins and Menu buttons at the bottom you have to touch-scroll, and every touch starts with a `pointerdown` on `#over`. After the 350 ms guard that `pointerdown` restarts the run. The summary's own "spend your shards" path (`overSkinsBtn`, plus the `goalText()` hint "You can afford X. Open Skins.") is therefore unusable there.

ATTACK 4 [MINOR] The doc's claim "`prefers-reduced-motion` … turns off the CSS animations" is false
Where: `@media (prefers-reduced-motion:reduce){ .card,.badge.on,.toast{animation:none;transition:none} }`.
Problem: `.toast.out{animation:toastOut .3s ease forwards}` has specificity (0,2,0), which beats `.toast` (0,1,0) inside the media query, so the toast exit animation still plays. `.skin.nope{animation:nope .35s}` (the shake on a denied purchase), the `.screen` opacity transitions, `.btn:active`/`.icon-btn:active` scale and the `.bar.wide i` 0.9 s transition are not covered either. On the canvas, the full-screen red flash on death (`G.flash = 1`, drawn at 0.35 alpha) and the slow-motion and hit-stop are not reduced at all. Only the shake amplitude and the HUD score pop change.

ATTACK 5 [MINOR] The doc's claim "From death to the summary takes 0.85 s, which includes the slow-motion" is wrong
Where: `frame()`: `if (G.hitstop > 0) { G.hitstop -= dt; render(); return; }` comes before `G.deadT += dt; … if (G.deadT > 0.85) finishRun();`, and `die()` sets `G.hitstop = 0.1`.
Problem: While the 0.1 s hit-stop runs, the function returns early, so `deadT` does not advance. The summary therefore appears 0.95 s after death, not 0.85 s. This is a small but checkable error in the timing the doc gives for the restart loop.
