ATTACK 1: CONCEDE. The empty catch made a blocked save invisible to the player. A small correction: modern Firefox private windows do allow localStorage writes and clear them when the session ends. Blocked-storage settings, however, really do throw, and the player was never told. Fix: the game now test-writes at startup, and `Save.ok`/`onFail` report any later write failure. Either way, a red notice appears on the menu and the result card, plus a one-time toast. Tested with `getItem`/`setItem` throwing `SecurityError`: the notice shows and the game is still playable.
ATTACK 2: CONCEDE. Fix: a new `commitRun()` saves best, bank, runs and achievements inside `die()`, in the frame of the hit. It is guarded so it runs once per run. It also runs on R/Restart, on Menu, and on `pagehide` mid-run, so abandoned runs no longer lose their shards either. Measured result: the save is written about 880 ms before the result card appears.
ATTACK 3: CONCEDE. Fix: every write path (run commit, purchase, achievement, mute) now calls `Save.refresh()` to re-read storage before it changes anything. A `storage` listener also re-syncs other tabs live, including an open Hangar. Tested with two tabs: one tab set the bank to 999 and added a core, and the other tab's Hangar showed 999 at once. A run that then ended in the first tab kept the core.
ATTACK 4: CONCEDE. Fix: `Sound.unlock()` now builds the whole audio graph inside a try/catch and assigns it only once it is complete. If that fails, it sets `failed` and the game runs silently. A rejected `resume()` promise is caught as well. Tested with an `AudioContext` constructor that throws: Play starts the run, and taps and M cause no errors.
ATTACK 5: CONCEDE. The claim was too strong. Scheduling the next frame first keeps the loop running, but a throw that repeats every frame would still freeze the screen. Fix: each frame now runs inside a try/catch that resets the canvas state. After three failed frames in a row, the game saves the run, resets to the menu and shows a one-time notice. The write-up now describes exactly this. Tested by making `arc()` throw mid-run: the game recovered to the menu, showed the toast, and the next run played normally.
